# 原版 M1/M2 Windows 基础启动安全审查

日期：2026-10-18。范围：原版 React/Express/SQLite 工程的配置损坏保护、本地 HTTP 防护及 windows/original-start.cjs 启动流程。本报告不涉及另一个离线看板。

已确认：

- 原有 config.json 损坏或 cloneRoot 无效时停止启动，不自动覆盖用户文件；有效配置保留原始格式。
- Windows 基础模式只允许指定回环 Host 与本地 UI/API Origin；WebSocket 仍使用原有 Host/Origin 检查。
- 启动器使用独立数据目录和子进程 cwd；SQLite、配置与附件上传目录因此与源码目录分开。基础模式明确禁用 AI 启动及执行。
- 已有 SQLite 数据库通过原生 SQLite backup API 创建快照并等待完成后，才允许启动服务器和迁移；备份失败中止，readonly 连接在 finally 中关闭。此机制包含 WAL 中已提交的数据，不采用仅复制主 db 文件的方式。
- 端口冲突不结束其他应用；独占数据目录锁不自动抢占，解除锁时核对所有权。停止仅针对本次启动的子进程。

独立检查结果：启动器 6 项测试通过；配置保护 3 项与 Windows 本地 HTTP 防护 2 项测试通过，共 11 项，无失败。

收尾检查：已向启动器负责人提出 dotenv override 使用空字符串、日志写入错误进入受控停止、spawn 失败时确保 close 清理、配置前置校验对齐服务端。等待修改后增量核对。

Windows 10 1909 双击启动及真实 Windows 进程退出仍需目标实机验证。完整原版门禁由 QA 单独记录，本报告的定向测试不能替代门禁或将 M1/M2 标记为已完成。

## 收尾增量核对

启动器收尾问题已修正并复核：dotenv override 为空字符串；日志流错误进入受控停止；spawn 失败无 PID 时不等待不存在的退出事件，正常子进程等待 close；配置数组与 NUL 路径在启动前拒绝。安装入口使用固定 npm 命令与清理后的环境，构建时显式提供空 VITE_API_KEY，防止源码 .env 将旧认证值嵌入客户端。安装只构建，不启动原版服务器或执行数据库迁移。

独立重跑启动器 6 项测试全部通过；新增安装 helper 语法检查通过。此前配置与本地防护共 5 项定向测试通过。**本轮范围内安全与架构审查通过，无未解决的源代码阻断项。** 最终整体验收仍以原版完整门禁及 Windows 1909 实机结果为准。

## M2 本机自检、诊断报告和快照预览增量审查

本轮审查仍限原版工程。诊断只读取配置格式、构建入口和环境，SQLite 使用内存实例；失败报告采用固定中文信息，不包含原始配置、cloneRoot 或环境变量。独立运行诊断 4 项测试通过。

本机自检使用 mkdtemp 创建的专属临时数据目录、动态回环端口和原版编译产物，不指向用户已有数据库；验证 React 静态资源、任务 CRUD、禁止 Agent 执行、重启持久化及备份可读。IPC 停止只通过父子进程通道存在，不增加 HTTP 停止接口。已提出异常启动器死亡时保留临时目录、失败报告去除绝对路径的收尾要求，等待增量核对。

快照只收集 config.json、SQLite backup API 导出的数据库及 data/uploads；不递归 cloneRoot、项目、日志、依赖或账号凭据目录。独占原版数据锁阻止与启动器并行，符号链接和非法条目拒绝。清单记录文件数、字节数和 SHA-256，验证真实文件集合并执行 SQLite integrity_check。独立运行快照 6 项测试通过，覆盖 WAL 已提交内容、散列篡改、额外文件、路径穿越、符号链接、持锁排斥、损坏源数据保留及预览不修改数据库。

当前恢复能力只有验证与预览，**没有写回、覆盖或 rollback/apply 实现**，不得描述为已恢复用户数据。SHA-256 用于完整性核验，不是来源真实性或数字签名。

## 本轮最终范围批准：自检、诊断、备份与显式恢复

前述待核对项已解决。自检现在逐个跟踪启动器停止请求与正常关闭确认；意外退出、IPC 失败或超时均保留临时数据，不以启动器死亡推定全部后代已停止。失败报告去除临时数据及应用目录的绝对路径。本人独立运行真实原版自检通过：1 项集成测试含 9 个内部检查，无真实 AI 调用。

恢复功能已在前述“仅预览”审查后扩展；以下结论取代该历史范围限制：

- 默认预览不写回；执行必须显式选择 apply，并精确确认清单快照 ID。CMD 通过 Node readline 读取路径和确认，用户路径不进入 shell 命令。
- 恢复前重新验证文件清单、路径、SHA-256、配置结构与 SQLite 完整性。Windows 设备名、尾部点/空格、冒号数据流、重复大小写路径及符号链接拒绝。
- 先成功创建并验证当前数据的安全快照，再暂存恢复文件；暂存再次核验散列。当前数据库/配置损坏而无法安全备份时拒绝执行，不能把此工具称为任意损坏修复器。
- 活跃 data 整目录及 config.json 通过重命名移至专属 recovery 目录，未知文件和 WAL/SHM 保留，不直接删除旧数据。捕获到中途安装失败时按已完成步骤回滚，并保留失败文件供检查。
- 第一次活跃重命名前写入并 fsync 恢复标记，记录安全快照、恢复路径与快照 ID。完整成功或完整回滚后才清除；回滚不完整保留标记。原版启动器在持有同一独占锁后、配置处理和迁移前备份之前检查任意未完成标记并停止；后续备份与 apply 同样拒绝。这是中断后的停止保护，不是自动崩溃恢复或断电原子性保证。

独立定向证据：备份/恢复 11 项、诊断 4 项、启动器 7 项、自检集成 1 项，合计 **23 项通过，无失败**。这些测试分组执行，均针对当前已审查的增量；完整应用门禁由 QA 单独给出。

**最终结论：本轮原版 M2 增量的安全、数据保护与实现范围审查通过，无未解决阻断项。** Windows 10 1909 的 CMD、文件重命名、原生 SQLite 与进程退出仍需目标实机验收，不得据 Linux 证据宣布 M1/M2 已完成。
