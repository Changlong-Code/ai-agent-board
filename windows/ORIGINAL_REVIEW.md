# 原版 M1/M2 Windows 基础启动安全审查

日期：2026-10-18。范围：原版 React/Express/SQLite 工程的配置损坏保护、本地 HTTP 防护及 windows/original-start.cjs 启动流程。本报告不涉及另一个离线看板。

已确认：

- 原有 config.json 损坏或 cloneRoot 无效时停止启动，不自动覆盖用户文件；有效配置保留原始格式。
- Windows 基础模式只允许指定回环 Host 与本地 UI/API Origin；WebSocket 仍使用原有 Host/Origin 检查。
- 启动器使用独立数据目录和子进程 cwd；SQLite、配置与附件上传目录因此与源码目录分开。基础模式明确禁用 AI 启动及执行。
- 已有 SQLite 数据库通过原生 SQLite backup API 创建快照并等待完成后，才允许启动服务器和迁移；备份失败中止，readonly 连接在 finally 中关闭。此机制包含 WAL 中已提交的数据，不采用仅复制主 db 文件的方式。
- 端口冲突不结束其他应用；独占数据目录锁不自动抢占，解除锁时核对所有权。停止仅针对本次启动的子进程。

独立检查结果：启动器 6 项测试通过；配置保护 3 项与 Windows 本地 HTTP 防护 2 项测试通过，共 11 项，无失败。

收尾检查：已向启动器负责人提出 dotenv override 使用空字符串、日志写入错误进入受控停止、spawn 失败时确保 close 清理、配置前置校验对齐服务端。等待修改后增量核对。

Windows 10 1909 双击启动及真实 Windows 进程退出仍需目标实机验证。完整原版门禁由 QA 单独记录，本报告的定向测试不能替代门禁或将 M1/M2 标记为已完成。

## 收尾增量核对

启动器收尾问题已修正并复核：dotenv override 为空字符串；日志流错误进入受控停止；spawn 失败无 PID 时不等待不存在的退出事件，正常子进程等待 close；配置数组与 NUL 路径在启动前拒绝。安装入口使用固定 npm 命令与清理后的环境，构建时显式提供空 VITE_API_KEY，防止源码 .env 将旧认证值嵌入客户端。安装只构建，不启动原版服务器或执行数据库迁移。

独立重跑启动器 6 项测试全部通过；新增安装 helper 语法检查通过。此前配置与本地防护共 5 项定向测试通过。**本轮范围内安全与架构审查通过，无未解决的源代码阻断项。** 最终整体验收仍以原版完整门禁及 Windows 1909 实机结果为准。
